# Questionnaire row contract (12A)

`POST /api/v1/ai/extractions/rfp` accepts either `{ "rows": [{ "rowId": "source-7", "question": "..." }], "documentIds": [...] }` or the existing `{ "content": "...", "documentIds": [...] }`. Row IDs and questions are nonempty; each question is at most 4,000 characters, each ID at most 200 characters, and the row count uses `PROVIDER_QUESTION_MAX`. Duplicate questions are separate rows. The caller should give each source row a stable ID; `index` is the zero-based input position and disambiguates even repeated IDs.

The response is `data: { version: 1, extractionAiInteractionId, results }`. `results` has exactly one entry per accepted input row, in input order: `{ rowId, index, question, status, answer, refused, confidence, citations, errorCode }`. `status` is `success`, `refusal`, or `error`. A row error has `answer` and `confidence` set to `null`, empty `citations`, and `errorCode: "ANSWER_FAILED"`; provider error details are not returned. A refusal retains its grounded answer text and sources if any. All results require staff review; this endpoint does not approve or submit answers.

For legacy `content`, extraction produces `extracted-1`, `extracted-2`, and so on in provider order. Those IDs do not claim to identify source spreadsheet rows. Malformed extraction output fails the request because no source rows are known. For explicit `rows`, malformed answer output becomes that row's `error`, and later rows continue. Request cancellation stops processing. The saved RFP n8n workflow is an inactive example; its mapped response includes row IDs and statuses, but its PDF/template handling and external nodes have not passed sandbox acceptance. Review, export and controlled delivery belong to 12C.

## Bounded development job (12B)

`POST /api/v1/questionnaires` accepts `{ "format": "TEXT" | "CSV", "content": "...", "documentIds": [...] }` from an authenticated ADMIN, MANAGER or REP. `GET /api/v1/questionnaires/:id` returns the same organization's ordered persisted rows. `POST /:id/cancel` cancels only unfinished rows; `POST /:id/rows/:rowIndex/retry` requeues one error row when its attempt count is below two. The existing workflow worker polls queued jobs. All rows are persisted before answering starts; the worker claims a fenced 60-second lease and renews it during work. Expired claims retain completed rows and retry only unfinished rows. Cancellation fences a running worker's later write.

Development input rules: UTF-8 JSON text with an optional BOM, at most 64 KiB, 1–50 rows (also capped by `PROVIDER_QUESTION_MAX`), IDs at most 200 characters, questions 3–1000 characters, and at most 20 document IDs. TEXT is one question per LF/CRLF line, with a single trailing newline allowed; IDs are `line-1`, `line-2`, etc. CSV requires the exact `rowId,question` header, two columns, LF/CRLF records, standard quoted commas/newlines and doubled quotes; blank rows/cells are rejected. Duplicate question text remains separate. These are engineering ceilings, **not buyer allowances or agreed pilot formats**.

Each row invokes the existing grounded-answer service, which applies its organization usage reservation and trace before provider work. Answer failures stay as `ERROR` rows with no provider detail in the API. A retry is explicit and limited to one additional attempt; exhausted rows remain for staff attention. A completed job may contain errors or refusals. No export, approval, sending, or client pilot inclusion is provided by this packet; review/export belongs to 12C, and 01C still owns actual pilot formats and limits.

## Staff review and CSV export (12C)

Each newly answered success or refusal row atomically checkpoints one system-authored draft and its generated revision. The draft carries the row's exact source references. Staff use the existing draft page to inspect sources, edit immutable revisions, and request exact-revision approval. Edits clear approval. Error, queued and cancelled rows have no draft; a successful explicit retry creates one. The questionnaire page shows ordered row IDs, questions, progress, error/refusal status and the current draft revision after reload. This is local review, not submission.

`GET /api/v1/questionnaires` lists the 50 most recent jobs for the signed-in organization. `GET /:id/export?includeSources=true|false` returns a UTF-8 CSV attachment. The fixed columns are `index,rowId,question,status,answer,draftId,revisionId,reviewStatus,sourceStatus,sources,errorCode`. All imported rows appear in original zero-based order, including unfinished, failed and cancelled rows. Repeated IDs or question text remain separate by `index`. The `answer` is the current saved draft revision when one exists; otherwise it is the original saved answer or an empty cell. Missing draft/revision/source IDs and error codes are empty cells. Review status is `APPROVED` only for a current approval with current or no sources; archived and stale cases are marked separately. Source IDs are included only when requested and every linked source remains current. Exports never send responses or change delivery state.

Every CSV cell is quoted; embedded quotes are doubled and embedded newlines remain inside the quoted cell. Cells whose first non-whitespace character is `=`, `+`, `-` or `@` gain a leading apostrophe before quoting. This policy targets common spreadsheet formula interpretation; importers with unusual formula rules require separate validation. Existing 12B rows created before this migration retain their raw answer and citations but have no linked draft until separately migrated; their CSV review status remains `REQUIRED`.
