# Questionnaire row contract (12A)

`POST /api/v1/ai/extractions/rfp` accepts either `{ "rows": [{ "rowId": "source-7", "question": "..." }], "documentIds": [...] }` or the existing `{ "content": "...", "documentIds": [...] }`. Row IDs and questions are nonempty; each question is at most 4,000 characters, each ID at most 200 characters, and the row count uses `PROVIDER_QUESTION_MAX`. Duplicate questions are separate rows. The caller should give each source row a stable ID; `index` is the zero-based input position and disambiguates even repeated IDs.

The response is `data: { version: 1, extractionAiInteractionId, results }`. `results` has exactly one entry per accepted input row, in input order: `{ rowId, index, question, status, answer, refused, confidence, citations, errorCode }`. `status` is `success`, `refusal`, or `error`. A row error has `answer` and `confidence` set to `null`, empty `citations`, and `errorCode: "ANSWER_FAILED"`; provider error details are not returned. A refusal retains its grounded answer text and sources if any. All results require staff review; this endpoint does not approve or submit answers.

For legacy `content`, extraction produces `extracted-1`, `extracted-2`, and so on in provider order. Those IDs do not claim to identify source spreadsheet rows. Malformed extraction output fails the request because no source rows are known. For explicit `rows`, malformed answer output becomes that row's `error`, and later rows continue. Request cancellation stops processing. The saved RFP n8n workflow is an inactive example; its mapped response includes row IDs and statuses, but its PDF/template handling and external nodes have not passed sandbox acceptance. Persistent job recovery, import/export rules and controlled delivery belong to 12B/12C.
