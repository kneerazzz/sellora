# Staff browser acceptance

Packet 10D uses Firefox 157.0.1 in headless mode, the production web bundle, the real Express API, and a newly created loopback PostgreSQL/pgvector container with temporary storage. The runner deploys migrations twice and removes its container even when an assertion fails. Document embeddings and answer generation use deterministic local fixtures; no live provider or client account is involved.

From `apps/web`, build with `VITE_API_URL=/api/v1 npm run build`. From `apps/server`, run `node scripts/integration/runDisposable.mjs --browser-only` for the focused browser suite or `npm run test:db` for the full inherited database suite. Both commands create their own disposable database. Do not point these scripts at a client database.

The browser fixture is `apps/server/scripts/integration/draftsBrowser.ts`. It checks visible mobile task navigation and focus; login labels; a real file upload through Knowledge; draft creation; the cited passage beyond the first 100 preview chunks; inert source markup and long passage layout; revision editing, exact approval and copy confirmation; a controlled failed save; clipboard denial; a concurrent edit from a second Firefox tab with 409 and retained local text; reload and approved-answer review/reuse; refusal blocking approval; stale-source redaction; session revocation followed by login and reopening; and a REP deep link redirected away from API keys. SQL checks the uploaded document, refusal, revision pointer, approval and export revision IDs, one copy confirmation, library lineage, and REP 403 responses. The 390-pixel viewport check covers horizontal overflow at login and the long source screen.

This is local Firefox acceptance with deterministic provider fixtures. It does not establish other browsers, deployed TLS/proxy behavior, real provider answer quality, buyer policy, or client acceptance. The existing dirty-link and unload checks do not exercise the browser toolbar Back action.
